> 이 문서는 Claude Code로 개발하기 위한 제품 요구사항 문서(PRD)입니다.
> 개발 시 **11. Claude Code 개발 가이드**를 먼저 확인하세요.

## 1. 제품 개요

**제품 정의**
- **분류:** 서버 없이 브라우저에서만 동작하는 단일 페이지 업무 지원 웹앱(SPA)
- **차별점:** 자유 형식 메모 앱과 달리 회의 내용을 '결정사항'과 '조치 과제(담당자·기한·상태)'로 구조화해 입력받아, 회의 결과 보고서를 자동 생성하고 여러 회의에 흩어진 미완료 과제를 한 화면에서 추적함

| 항목 | 내용 |
|---|---|
| 제품명(가칭) | 회의 후속조치 관리 도구 (Meeting Follow-up Tracker) |
| 형태 | 정적 웹앱 (HTML / CSS / Vanilla JavaScript) |
| 소스 관리 | GitHub 저장소 |
| 배포 | Vercel (GitHub 저장소 연동, 정적 사이트) |
| 제출물 | Vercel 배포 URL (`https://{프로젝트명}.vercel.app`) |
| 데이터 저장 | 브라우저 localStorage |
| 파일 구성 | index.html, style.css, app.js (+ README.md, .gitignore) |

## 2. 문제 정의와 목표

### 2.1 해결할 문제
- 회의록 형식이 사람마다 달라 결정사항과 조치 과제가 본문 속에 묻힘
- "누가, 무엇을, 언제까지"가 회의별로 흩어져 후속 조치가 누락됨
- 회의 결과 보고서를 매번 수작업으로 재정리해야 함
- 다음 회의 전 이행 상황 점검 시 지난 회의록을 일일이 열어봐야 함

### 2.2 제품 목표

| 목표 | 성공 기준 |
|---|---|
| 회의 결과 정리 시간 단축 | 회의 1건 입력부터 보고서 출력까지 5분 이내 |
| 후속 조치 누락 방지 | 모든 조치 과제에 담당자·기한 필수 입력 |
| 이행 상황 가시화 | 미완료·임박·지연 과제를 한 화면에서 확인 |
| 도입 장벽 제거 | 설치·로그인 없이 배포 URL 접속만으로 사용 |

## 7. 데이터 구조

localStorage 키 `mft_data_v1` 하나에 전체 데이터를 JSON으로 저장합니다.

```json
{
  "version": 1,
  "meetings": [
    {
      "id": "m_1730600000000",
      "title": "주간 업무회의",
      "datetime": "2026-11-03T10:00",
      "location": "3층 회의실",
      "attendees": ["김OO", "이OO", "박OO"],
      "agendas": ["프로젝트 일정 점검", "예산 집행 현황"],
      "decisions": [
        { "id": "d_1730600001000", "content": "○○ 일정을 11월 말로 확정" }
      ],
      "actions": [
        {
          "id": "a_1730600002000",
          "content": "요건 정의서 초안 작성",
          "owner": "김OO",
          "dueDate": "2026-11-07",
          "status": "IN_PROGRESS",
          "completedAt": null,
          "createdAt": "2026-11-03T11:00:00"
        }
      ],
      "createdAt": "2026-11-03T11:00:00",
      "updatedAt": "2026-11-03T11:20:00"
    }
  ]
}
```

**설계 원칙**
- 결정사항·조치 과제는 회의 객체 안에 중첩 저장 → 회의 삭제 시 하위 데이터 자동 정리
- 미완료 현황은 모든 회의의 `actions`를 평탄화(flatten)해서 계산, 별도 인덱스 없음
- 상태 코드값: `TODO`(미착수), `IN_PROGRESS`(진행중), `DONE`(완료). 화면 표시 시 한글 라벨로 변환
- ID: 접두어 + 타임스탬프(+ 난수). `crypto.randomUUID()` 사용 가능 시 사용
- 날짜: ISO 문자열 저장 (`dueDate`는 `YYYY-MM-DD`)

## 8. 기술 설계

### 8.1 파일별 역할

| 파일 | 역할 |
|---|---|
| index.html | 헤더·탭·푸터 등 고정 레이아웃, 본문 컨테이너 `<main id="app">`, 상대 경로로 CSS/JS 로드 |
| style.css | CSS 변수로 색상 관리, 반응형, 상태 배지·강조 색, 토스트, `@media print` |
| app.js | 상태 관리, 저장소, 라우팅, 렌더링, 이벤트 처리 |
| README.md | 프로젝트 소개, 기능, 배포 URL, 로컬 실행 방법 |
| .gitignore | `.DS_Store`, `.vercel`, `node_modules` 등 제외 |

### 8.2 app.js 내부 구성 (주석으로 영역 구분)

| 영역 | 담당 |
|---|---|
| Constants | 저장 키, `DUE_SOON_DAYS`, 상태 라벨 맵 |
| Store | `load()`, `save()`, 회의·결정사항·과제 CRUD, 샘플 데이터 생성 |
| Utils | ID 생성, 날짜 파싱, D-day 계산, 기한 상태 판정, HTML 이스케이프, 토스트 |
| Router | `hashchange` / `DOMContentLoaded` 시 해시 해석 후 render 함수 호출 |
| Views | `renderMeetingList`, `renderMeetingForm`, `renderMeetingDetail`, `renderReport`, `renderActions` |
| Report | 보고서 HTML 생성 함수, 복사용 텍스트 생성 함수 (분리) |
| Events | `#app`에 이벤트 위임, `data-action` 속성으로 동작 분기 |

### 8.3 구현 방침
1. **단방향 흐름:** 사용자 입력 → Store 변경 → `save()` → 현재 화면 재렌더링. DOM을 데이터 원본으로 쓰지 않음
2. **해시 라우팅:** `#/경로` 방식 사용. Vercel 정적 배포에서 추가 설정(`vercel.json` rewrites) 없이 새로고침·직접 접속이 동작함
3. **렌더링:** 템플릿 리터럴 + `innerHTML`. 모든 사용자 입력은 `escapeHtml()`로 이스케이프(XSS 방지)
4. **날짜 계산:** 시간 제외 날짜 단위로 비교. `YYYY-MM-DD`를 `new Date(y, m-1, d)`로 로컬 날짜 파싱해 시간대 오차 방지
5. **인쇄:** `window.print()` + `@media print`에서 헤더·푸터·버튼 숨김
6. **텍스트 복사:** `navigator.clipboard.writeText()` 우선, 실패 시 textarea 선택 + `document.execCommand('copy')` 대체
7. **입력 검증:** 필수값 누락 시 저장 차단, 필드 아래 오류 메시지 표시
8. **예외 처리:** localStorage 파싱 오류·용량 초과를 `try/catch`로 처리, 손상 데이터로 앱이 멈추지 않게 함

## 10. 배포 (GitHub + Vercel)

### 10.1 저장소 구조
```
meeting-followup-tracker/
├── index.html
├── style.css
├── app.js
├── README.md
└── .gitignore
```
- 모든 파일은 저장소 **루트**에 위치 (Vercel 기본 설정으로 바로 서빙)
- 파일명은 소문자, 리소스 참조는 상대 경로(`./style.css`, `./app.js`) 사용 → Vercel은 대소문자를 구분하므로 주의
- `package.json`을 만들지 않음 (Vercel이 정적 사이트로 인식하도록)

### 10.2 배포 절차
1. GitHub에 새 저장소 생성 후 코드 push (`main` 브랜치)
2. Vercel 로그인(GitHub 계정 연동) → **Add New… → Project** → 해당 저장소 **Import**
3. 설정
   - Framework Preset: **Other**
   - Root Directory: `./`
   - Build Command: 비워둠 (없음)
   - Output Directory: 비워둠 (루트 그대로 서빙)
4. **Deploy** 클릭 → `https://{프로젝트명}.vercel.app` 발급
5. 이후 `main`에 push할 때마다 자동 재배포

### 10.3 제출 전 점검 체크리스트
- [ ] 배포 URL을 **시크릿 창**에서 열어도 샘플 데이터와 함께 정상 표시
- [ ] 각 해시 경로에서 새로고침 시 같은 화면 유지
- [ ] 브라우저 콘솔(F12)에 오류 없음
- [ ] CSS·JS 로드 실패(404) 없음
- [ ] 모바일 화면에서 레이아웃 정상
- [ ] 인쇄 미리보기에 보고서만 출력
- [ ] 텍스트 복사 동작 (HTTPS 환경)
- [ ] README.md에 배포 URL 기재
- [ ] Vercel 프로젝트가 Public 접근 가능 (Deployment Protection 해제 확인)

> 참고: Vercel 프로젝트 설정의 Deployment Protection이 켜져 있으면 프리뷰 URL에 로그인이 요구될 수 있습니다. 강사에게는 **Production 도메인**(`{프로젝트명}.vercel.app`)을 제출합니다.

## 12. 제약사항과 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| localStorage는 브라우저·기기별 저장 | 강사·다른 PC에서는 내 데이터가 보이지 않음 | 첫 실행 샘플 데이터 제공, JSON 내보내기·가져오기, 화면 안내 |
| 브라우저 데이터 삭제 시 손실 | 기록 소실 | 백업(내보내기) 권장 문구 |
| 용량 제한(약 5MB) | 장기 사용 한계 | 텍스트 위주라 충분, 저장 실패 시 경고 |
| 클립보드 API는 HTTPS 필요 | 로컬 파일 실행 시 복사 실패 가능 | 대체 복사 방식 구현, Vercel은 HTTPS 기본 제공 |
| 파일명 대소문자 불일치 | Vercel(Linux)에서 404 | 소문자 파일명·상대 경로 통일 |
